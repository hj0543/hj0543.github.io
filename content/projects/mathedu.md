## 프로젝트 개요

**mathedu(매쓰듀)**는 중학생의 수학 학습 과정에서 발생하는 오답을 단순히 기록하는 데 그치지 않고, **어떤 개념과 유형에서 반복적으로 틀리는지를 관리하고 복습할 수 있도록 돕는 수학 학습 관리 서비스**입니다.

학생의 문제 풀이 결과를 누적하여 단원별 학습 상태와 반복되는 오답 유형을 확인하고, 이를 바탕으로 부족한 영역을 다시 학습할 수 있는 구조를 기획하고 있습니다.

수학학원에서 직접 학생들을 지도하며 경험했던 **오답 관리, 학습 이력 파악, 반복 학습 관리에 들어가는 업무를 효율화하는 것**을 프로젝트의 핵심 목표로 두고 있습니다.

---

## 개발 배경 및 필요성

* **교육 현장에서 느낀 반복 업무의 비효율**

  * 수학학원에서 근무하며 학생별 진도, 시험 결과, 오답 문제와 취약 단원을 지속적으로 파악해야 했습니다.
  * 학생 수가 많아질수록 각 학생이 과거에 어떤 문제를 틀렸고, 동일한 유형에서 반복적으로 실수하고 있는지를 지속적으로 관리하기 어려웠습니다.

* **단순한 오답 기록을 넘어선 학습 이력 관리**

  * 학생이 문제를 다시 푸는 것만으로는 같은 유형의 실수가 반복되는 원인을 확인하기 어렵다고 느꼈습니다.
  * 오답을 단원·유형·오답 원인 등의 기준으로 누적하여 학생의 학습 상태를 장기적으로 확인할 수 있는 서비스를 기획했습니다.

* **교육의 효율화**

  * 수학학원에서 근무하며 교육 과정에서 반복적으로 발생했던 관리 업무를 줄이고, 학생의 취약점을 보다 빠르게 파악할 수 있도록 실제 현장에서 필요하다고 느꼈던 기능들을 직접 구현하고자 기획했습니다.

## 주요 기능

### 1. 문제 및 학습 기록 관리

* 학습한 문제 및 시험 결과 등록
* 정답·오답 여부 기록
* 단원 및 문제 유형별 분류
* 학생별 문제 풀이 이력 관리
* 날짜별 학습 기록 조회

### 2. 오답 관리

* 틀린 문제 자동 누적
* 단원·유형별 오답 분류
* 계산 실수, 개념 부족, 문제 해석 오류 등 오답 원인 기록
* 동일 문제 재풀이 여부 관리
* 반복해서 틀리는 문제 및 유형 확인

### 3. 취약 단원 및 유형 분석

누적된 학습 결과를 기반으로 학생이 어떤 영역에서 어려움을 겪고 있는지 확인할 수 있도록 합니다.

* 단원별 정답률
* 문제 유형별 정답률
* 반복 오답 횟수
* 오답 원인 분포
* 최근 학습 성취도 변화

### 4. 복습 관리

오답을 단순히 저장하는 것이 아니라 다시 학습할 수 있도록 복습 과정을 관리합니다.

* 복습이 필요한 문제 확인
* 오답 문제 재풀이
* 재풀이 결과 기록
* 복습 완료 여부 관리
* 반복 오답 문제 별도 관리

### 5. 학습 대시보드

학생의 현재 학습 상태를 한 화면에서 확인할 수 있도록 구성합니다.

* 전체 문제 풀이 수
* 최근 정답률
* 단원별 성취도
* 취약 단원
* 반복 오답 유형
* 복습이 필요한 문제
* 기간별 학습량 변화

### 6. 학습 리포트

일정 기간 동안의 학습 데이터를 정리하여 단순한 점수가 아니라 **학생이 어떤 부분에서 성장했고 어떤 부분이 부족한지** 확인할 수 있도록 합니다.

* 기간별 학습량
* 정답률 변화
* 취약 단원 변화
* 반복 오답 감소 여부
* 복습 진행 현황

## 기술적 고민 및 문제 해결

> 개발 진행 후 실제 발생한 문제와 해결 과정을 기록할 예정입니다.

현재 기획 단계에서는 다음 항목을 주요 기술적 고려사항으로 두고 있습니다.

### 문제를 어떤 기준으로 분류할 것인가

단순히 문제를 '방정식', '함수'와 같은 단원 단위로만 구분하면 학생이 실제로 어려움을 겪는 세부 유형을 파악하기 어렵습니다.

따라서 **대단원 → 소단원 → 문제 유형**으로 이어지는 문제 분류 구조를 설계하고, 하나의 문제에 여러 학습 요소가 포함될 수 있는 경우까지 고려할 예정입니다.

### 오답을 어떻게 데이터로 표현할 것인가

같은 문제를 틀렸더라도 개념을 몰라서 틀린 경우와 계산 실수로 틀린 경우에는 필요한 복습 방법이 다릅니다.

정답 여부뿐만 아니라 오답 원인을 별도의 데이터로 관리하여 학생의 반복적인 실수 패턴을 분석할 수 있는 구조를 고민하고 있습니다.

### 반복 학습 이력을 어떻게 관리할 것인가

한 문제를 최초 풀이와 재풀이로 나누지 않고 현재 상태만 저장하면 학생이 실제로 오답을 극복했는지 확인하기 어렵습니다.

따라서 문제의 상태를 덮어쓰는 방식보다 **각 풀이를 학습 기록으로 누적하는 구조**를 설계하여 최초 풀이부터 복습까지의 변화를 추적할 예정입니다.
