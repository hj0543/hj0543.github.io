## 프로젝트 개요

**주차콜**은 교회 주차봉사자가 이중주차나 출구를 막은 차량의 차주를 빠르게 찾아 연락할 수 있도록 만든 앱입니다. 번호판을 촬영하거나 뒤 4자리를 입력해 등록 차량을 조회하고, 결과 화면에서 전화 또는 문자를 바로 보낼 수 있습니다.

## 개발 배경 및 필요성

주차 현장에서 차주를 찾기 위해 방송하거나 주변에 수소문하면 시간이 걸립니다. 주차봉사자가 한 손으로 차량을 조회하고 바로 연락할 수 있는 흐름을 설계했습니다. 차주명과 연락처는 민감한 정보이므로 기기 안에 암호화해 저장하도록 구성했습니다.

## 주요 기능

- **번호판 검색:** 카메라로 번호판을 인식하거나 번호 뒤 4자리로 검색합니다. 인식 결과는 확인하고 수정할 수 있습니다.
- **차주 연락:** 검색 결과에서 전화 앱이나 문자 앱으로 이동합니다. 교회명과 차량번호를 넣는 문자 문구를 설정할 수 있습니다.
- **차량 등록·관리:** 차주명, 연락처, 소속, 차량 정보와 메모를 등록하고 수정·삭제합니다. 중복 번호판을 확인하고 구두 동의 여부를 필수로 받습니다.
- **최근 검색:** 홈 화면에서 최근 조회한 차량에 다시 접근할 수 있습니다.
- **잠금과 백업:** 6자리 PIN, 자동 잠금, 지원 기기의 생체 인증을 제공하고, 별도 비밀번호로 암호화한 `.pms` 파일을 내보내거나 복원합니다.

## 담당 역할 및 기여

개인 프로젝트로 서비스 흐름과 화면을 설계하고 React Native 앱, 로컬 데이터 저장·암호화, 번호판 인식 연동, OCR용 Django API를 구현했습니다.

## 시스템 아키텍처

```text
Expo React Native 앱
├─ 차량 · 연락처 · 검색 기록 · 설정 → 기기 내부 암호화 저장
├─ PIN → PBKDF2-SHA256 → AES-256-GCM 암호화 키
├─ Android: 내장 OCR 모델로 번호판을 기기 안에서 인식
└─ 웹 · iOS: 번호판 사진 → Django OCR API → PaddleOCR
                              └─ 사진과 차주 정보는 서버에 저장하지 않음
```

Android에서는 인터넷이나 서버 없이 번호판 인식과 차량 등록을 처리합니다. 웹과 iOS의 OCR 요청은 사진만 서버로 보내며, 차량·연락처 데이터와 검색은 기기 안에서 처리합니다. 웹 데이터는 IndexedDB에, 모바일 데이터는 앱 문서 저장소에 암호화해 저장합니다.

## 기술적 고민 및 문제 해결

### 개인정보를 서버에 저장하지 않는 구조

차량번호와 연락처를 서버 데이터베이스에 모으면 주차 현장 검색을 위해 네트워크에 의존하고, 유출 범위도 커집니다. 앱에서 PIN으로 암호화 키를 만들고 전체 데이터를 기기 내부에 암호화해 저장했습니다. 잠금 시 키를 메모리에서 지우며, 서버는 웹·iOS의 OCR 요청만 처리합니다.

### 번호판 인식 환경의 차이

Android 앱에는 한국어 OCR 모델을 포함해 촬영한 번호판을 기기 안에서 인식하도록 했습니다. 웹과 iOS는 Django API에서 PaddleOCR로 인식하되 사진을 저장하지 않습니다. 인식 오류에 대비해 후보 확인·수정과 번호 뒤 4자리 검색을 함께 제공합니다.

### 기기 변경과 PIN 분실에 대비한 복원

로컬 저장만으로는 앱 삭제나 기기 분실 시 데이터가 사라질 수 있습니다. 별도 비밀번호로 암호화한 `.pms` 백업 파일을 내보내고 복원하는 기능을 구현했습니다. PIN을 잊은 경우에도 백업 비밀번호와 파일로 데이터를 복원하며 새 PIN을 설정할 수 있습니다.
