## 프로젝트 개요

**도담**은 사용자가 설정한 금융 목표를 기준으로 계좌·소비·카드·대출·예적금 데이터를 통합 진단하고, 목표 달성을 방해하는 요인을 찾아 개선 행동별 효과를 수치로 비교해 주는 개인 금융 코치 서비스입니다.
"어린아이가 탈 없이 잘 자라는 모양"이라는 뜻처럼, 청년의 금융생활과 자산이 무리 없이 건강하게 자라도록 돕는 것을 목표로 합니다.

대표 페르소나는 취업 6개월 차 사회초년생(월 실수령 230만 원, 월세·학자금대출·적금·카드 3장·OTT 정기결제 보유)이지만, 서비스 대상을 특정 연령층으로 제한하지는 않습니다.

## 개발 배경 및 필요성

- 기존 자산관리 앱은 금융현황과 소비내역을 **보여주는 데** 강점이 있지만, 현재 상태가 **내 목표 달성에 적절한지**는 알려주지 않음
- 소비 증가, 높은 대출금리, 유휴자금 등 개선 여지가 동시에 존재할 때 **무엇부터 고쳐야 효과적인지** 판단하기 어려움
- 소비를 줄이거나 대출 조건을 바꾸는 선택이 실제 목표 달성 시점에 **얼마나 영향을 주는지** 미리 확인할 수 없음
- 카드결제·대출상환·적금납입·월세가 겹치는 시점의 **단기 현금 부족**을 사전에 인지하기 어려움
→ "목표 기준으로 개선요인을 탐지 → 행동별 효과를 비교 → 실행 이후 변화를 추적"하는 코치형 서비스가 필요하다고 판단

## 주요 기능

- **금융 현황 통합 조회**: SSAFY 교육용 금융망 연동으로 계좌·거래를 수집하고, 카드·할부·대출·마이너스통장·예적금·정기결제를 한 화면에서 파악
- **목표 설정**: 모으기 목표(목표 금액·기한 → 필요 월 저축액 계산)와 줄이기 목표(월 소비 예산 → 남은 가용액·소비 속도 기반 예상치)
- **현금흐름 예측·위험 탐지**: 예정 입출금을 일 단위로 시뮬레이션해 잔액 부족 시점과 심각도를 사전에 경고
- **금융 진단**: 목표 이탈·현금흐름 위험 등 규칙 기반 진단 + 익명 소비 유형 군집과 비교하는 보조 탐지(Hybrid)
- **개선 추천**: 진단 결과를 바탕으로 저축 증액·소비 감축·부족액 확보 등 행동을 위험도·효과·목표 기여도·시급성 점수로 우선순위화
- **시뮬레이션**: 소비 감소, 저축 변경, 예적금 가입, 신규 대출·추가상환·대환, 할부·리볼빙·현금서비스, 그리고 이들을 조합한 복합 시나리오의 목표 달성일 변화를 비교
- **대출 분석**: 월 상환 부담률, 만기까지 예상 이자, 대출별 비용 비교, 금리 비교, 상환 우선순위
- **금융상품 조회·비교**: 예적금·대출·카드 상품 카탈로그 조회 및 사용자 상황 기반 비교
- **소셜 로그인·알림**: 카카오/구글 로그인, FCM 푸시 알림

## 기술적 고민 및 문제 해결

### 1. 시뮬레이션 중복 실행 방지와 재현성
- **문제**: 같은 조건으로 시뮬레이션을 여러 번 실행하면 결과 행이 쌓이고, 상품 금리가 바뀌면 같은 요청도 다른 결과가 나와 이전 결과와 비교할 수 없음. ERD에는 멱등 키 컬럼이 없고 요청 파라미터는 JSON이라 DB UNIQUE로 막을 수 없음
- **해결**: `(userId, type, 정규화된 입력 지문, 기준일, 계산 버전)`의 SHA-256 요청 해시를 스냅샷에 저장하고, 같은 날 같은 지문이면 기존 건을 반환(200)하고 새 조건이면 생성(201). 동시 요청은 사용자 행 `PESSIMISTIC_WRITE` 잠금으로 직렬화. 계산식이 바뀌면 계산 버전을 올려 이전 결과를 재사용하지 않도록 함
- **효과**: 실행 결과의 before/after 스냅샷이 보존되어 조건 변경 전후 비교가 가능하고, 복합 시나리오 자식 9종의 순서를 바꿔도 집계 결과가 동일함을 통합 테스트로 고정

### 2. 진단 → 추천 → 시뮬레이션 간 계산 일관성
- **문제**: 추천이 제시한 효과(예: 월 20만 원 절감)와 실제 시뮬레이션 결과가 다르면 사용자가 서비스를 신뢰할 수 없음. 진단은 "이번 달", 시뮬레이션 기준선은 "직전 3개월"을 읽어 데이터 창이 다름
- **해결**: 추천 생성기가 현재 데이터를 재계산하지 않고 **진단이 저장한 스냅샷만** 읽도록 순수 함수로 설계. 추천 응답에 시뮬레이션 프리셋(엔드포인트+요청 본문)을 포함해 클릭 한 번으로 같은 값을 실행. 추천 효과 = 시뮬레이션 `after − before` 등식을 API 수준 테스트로 고정하고, 예상 달성일은 목표 도메인과 동일 식·동일 기준일로 계산
- **효과**: 규칙 버전(`v3-goal-impact`, 생성기 `548.1`)을 명시해 규칙 변경 시 캐시 재사용 범위가 분리되고, 두 창의 차이는 문서와 fixture에 명시

### 3. 현금흐름 위험 판정 시점
- **문제**: 하루 마감 잔액으로 부족을 판정하면 같은 날 여러 출금 중 어느 건에서 막히는지 알 수 없고, 한 번 음수가 되면 이후 날짜가 전부 위험으로 잡혀 목록이 무의미해짐
- **해결**: 하루 안에서 입금을 먼저 반영한 뒤 **각 출금 직전 잔액**으로 판정. 탐지를 잔액 순회 계산기 안에서 함께 수행해 입출금 반영 순서가 두 곳으로 갈라지지 않도록 함
- **효과**: 위험이 "어느 날 어떤 출금에서 얼마 부족"으로 특정되어 진단·추천의 입력으로 그대로 연결

### 4. 민감한 금융 정보 보호
- **문제**: 카드번호·계좌번호를 조회 키로 써야 하지만 원문 저장·단순 해시는 유출 시 복원 가능
- **해결**: 암호화 키와 분리된 키를 쓰는 **HMAC-SHA-256 해시 컬럼**으로 조회, 원문은 **AES-256-GCM**(매번 새 IV)으로 암호화, 응답은 마스킹 값만 제공. 조회 전용 엔티티는 암호문 컬럼을 매핑조차 하지 않음. 모든 리소스 조회에 소유권 조건 포함, 타인 리소스는 존재 여부를 노출하지 않도록 404 처리
- **효과**: 응답·로그·시뮬레이션 스냅샷 어디에도 원문·해시가 남지 않음을 테스트로 검증

### 5. 외부 금융망 장애 격리
- **문제**: SSAFY 금융망 지연·오류가 조회 API 전체 장애로 전파될 수 있음
- **해결**: 연결 3초·읽기 5초 타임아웃과 전용 예외(`SsafyUnavailableException`)로 503 응답에 매핑. 카드·대출·예적금 등 분석 API는 동기화된 로컬 데이터를 읽어 금융망 연결 여부와 무관하게 동작
- **효과**: 외부 장애가 진단·추천·시뮬레이션 흐름에 영향을 주지 않음
