Ait의 스터디 라운지에는 함께 면접을 연습하는 화상 스터디룸이 있다. LiveKit으로 화상 세션을 붙이고, 그 위에 화면 공유, 그룹톡, 자료실, 상호 평가를 얹었다. [리더 회고](/devlog/2026-08-17-ait)에서는 코드 밖의 이야기를 남겼으니, 여기서는 화상 화면 하나를 만들며 부딪힌 두 가지 문제를 정리한다.

## 1. 화면과 실제 상태가 어긋났다

참여자가 들어오고 나가고, 마이크를 끄고, 화면을 공유한다. 이 일들이 동시에 일어나자 화면이 실제 상태와 어긋나기 시작했다. 분명 마이크를 켰는데 타일에는 음소거 아이콘이 그대로 남아 있었고, 이미 나간 사람의 타일이 검은 화면으로 한동안 자리를 지키기도 했다.

원인은 같은 상태를 두 곳에서 들고 있었기 때문이다. LiveKit은 이미 트랙 상태를 알고 있는데, 컴포넌트도 "이 사람은 음소거 중"이라는 상태를 따로 들고 있었다. 두 상태를 맞추는 코드가 늘어날수록, 맞추지 못한 틈도 함께 늘어났다.

## 2. 상태의 출처를 LiveKit 하나로

그래서 컴포넌트가 상태를 들고 있지 않게 했다. 모든 상태는 LiveKit 이벤트에서만 나온다.

- Room 연결과 트랙 구독은 세션 컴포넌트 하나가 맡는다.
- 하위 컴포넌트에는 `RoomContext`로 Room을 내려준다.
- 각 타일은 카메라, 마이크, 화면 공유 트랙을 소스별로 따로 구독한다.

이렇게 바꾸고 나니 상태를 맞추는 코드 자체가 사라졌다. 누군가 마이크를 끄면 그 사람의 타일만 다시 그려지고, 다른 타일은 영향을 받지 않는다.

## 3. 열 수를 고르지 말고 계산하기

두 번째 문제는 레이아웃이었다. 처음에는 참여자 수에 따라 열 수를 분기했다. 두 명이면 2열, 다섯 명이면 3열 하는 식이다. 그런데 영상은 4:3 비율이라, 화면 크기에 따라 타일 위아래나 양옆으로 빈 여백이 크게 남았다. 사람이 늘수록 영상은 지나치게 작아졌다.

규칙을 정해 두는 대신 매번 계산하기로 했다. 가능한 열 수를 하나씩 대입해 보고, 타일 하나가 실제로 가장 크게 보이는 배치를 고른다.

<!-- TODO: 실제 코드로 교체 (아래는 설명용으로 단순화한 코드) -->

```ts
function bestColumns(count: number, width: number, height: number) {
  let best = { cols: 1, area: 0 };
  for (let cols = 1; cols <= count; cols++) {
    const rows = Math.ceil(count / cols);
    const tileW = Math.min(width / cols, (height / rows) * (4 / 3));
    const area = tileW * tileW * (3 / 4);
    if (area > best.area) best = { cols, area };
  }
  return best.cols;
}
```

컨테이너 크기나 참여자 수가 바뀔 때마다 이 계산을 다시 한다. 참여자가 몇 명이든, 창 크기가 어떻든 영상이 가장 크게 보인다.

## 4. 화면 공유가 끝나면 어디로 돌아갈까

화면 공유가 시작되면 레이아웃이 흔들렸다. 공유 화면을 크게 보여야 하는지, 누가 공유를 끝냈을 때 어디로 돌아가야 하는지가 코드 곳곳에 흩어져 있었다.

그래서 보기 상태를 세 가지로 명시했다.

- **그리드**: 모든 참여자를 고르게
- **특정 참여자**: 한 사람을 크게
- **화면 공유**: 공유 화면을 크게

상태가 이름을 갖고 나니 전이도 분명해졌다. 보고 있던 화면 공유가 끝나면, 남아 있는 다른 공유 화면으로 넘어가고, 없으면 그리드로 돌아간다.

## 돌아보며

- 같은 상태를 두 곳에서 들고 있으면, 맞추는 코드가 버그가 된다. 출처는 하나만 둔다.
- 경우의 수를 분기로 나누기보다, 기준을 정하고 계산한다.
- 화면의 모드는 암묵적으로 두지 말고 이름을 붙인다.

실시간 화면은 처음이었다. 정적인 화면은 내가 그린 대로 멈춰 있지만, 화상 화면은 내가 보지 않는 사이에도 계속 바뀐다. 누군가 들어오고, 나가고, 말을 하고, 화면을 띄운다. 그 모든 변화를 내가 쥐고 있으려 할수록 화면은 더 자주 어긋났다. 상태를 내려놓고 흐름을 믿었을 때에야 화면이 안정됐다. 붙잡는 것보다 맡기는 게 더 어려웠고, 그래서 더 많이 배웠다.
