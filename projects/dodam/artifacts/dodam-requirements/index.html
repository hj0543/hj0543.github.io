기획 산출물

도담 요구사항 정의서 · 공개 요약본

금융 목표를 기준으로 현재 상태를 진단하고, 행동별 효과를 비교한 뒤 목표 자금 관리까지 이어 주는 개인 금융 코치.

도담은 금융정보를 확인한 사용자가 **“그래서 지금 무엇을 바꾸면 내 목표에 가까워질까?”**에 답할 수 있도록 만든 앱이다. 소비·저축·대출 정보를 목표와 연결하고, 개선 행동을 선택했을 때 예상 달성일과 금융비용이 어떻게 달라지는지 보여 준다.

이 문서는 프로젝트 종료 후 기획·리뷰·QA 기록과 소스코드를 바탕으로 재구성한 요구사항 정의서의 요약본이다.

핵심 흐름과 요구사항 영역

핵심 흐름은 목표 설정 → 현황 진단 → 행동별 효과 비교 → 목표 자금 배정 → 변화 확인이다.

영역 사용자가 얻어야 할 결과
금융현황 내 금융정보의 출처와 연결 상태를 알고, 자산·소비를 확인한다.
목표 설정 목표 금액·기한에 필요한 저축액과 예상 달성일을 확인한다.
근거 있는 진단 목표 지연·소비 증가·금리 편차의 근거를 보고 점검할 항목을 찾는다.
행동 비교 소비 절감·저축 변경·대출 상환이 비용과 목표 달성일에 주는 차이를 비교한다.
목표별 자금 배정 도담 계좌의 돈을 목표별로 나눠 담고, 배정 가능한 금액을 확인한다.
AI 상담 자신의 질문을 계산 도구에 연결하고, 근거가 있는 수치와 설명을 받는다.
소비 예측 다음 달 변동 소비의 예상 범위와 계산 근거를 확인한다.
변화 확인 목표 진행률·브리핑·리포트로 변화를 확인한다.

교육용 금융망과 합성·시연 데이터를 기준으로 했다. 실제 대출·대환 실행, 투자 거래·종목 추천, 사용자 확인 없는 자동 자금 이동은 범위에서 제외했다.

내 역할

팀장·PM과 백엔드 개발을 맡았다.

구분 직접 맡은 범위
기획·정책 문제 정의와 서비스 방향, 목표 중심 이용 흐름과 기능 우선순위 정리, 진단·행동 비교의 기준 구체화
일정·협업 담당자와 선행 작업 정리, API 연동 조율, 통합 QA 진행 관리와 최종 발표 준비
핵심 계산 구현 진단·추천·시뮬레이션, 소비·현금흐름 예측, 금융상품·대출 등 담당 도메인 구현
자금 관리 전용 계좌와 목표별 세이프박스의 설계·구현, 목표 생성·상세 화면을 배정 흐름으로 연결
AI 코치 기여 서버 계산과 설명의 경계 정리, 소비 예측 조회 도구와 대출 추가상환 답변 보완

인증·일반 계좌 및 목표 기본 기능, 패턴 분석, 알림, 앱 화면과 인프라는 팀원들과 나눠 구현했다.

우선순위 기준

구분 선정 기준 대표 요구
M · 필수 핵심 이용 흐름에 필요하거나, 누락 시 타인 정보 노출·잘못된 계산·중복 자금 배정이 발생할 수 있는 조건 목표 계산, 진단 근거, 행동 비교, 배정 한도, 인증·소유권, 미계산·실패 상태 구분
S · 권장 핵심 흐름을 보조해 해석·비교·접근 편의를 높이는 기능 소비 유형·또래 비교·소비 예측, 음성 입력, 브리핑 시간 설정
C · 확장 별도 데이터·정책·화면이 필요한 추가 시나리오 휴면·혜택 등 확장 진단, 신규 대출·할부·리볼빙 등 추가 시뮬레이션

M에는 기능뿐 아니라 검증·예외 조건도 포함했다. 개발은 인증·금융 연결·목표 계산 → 진단·개선안·시뮬레이션 → 목표별 배정·리포트 순서로 의존관계를 따라 진행했다.

핵심 설계 결정

1. 계좌를 채우는 것과 목표에 담는 것을 분리했다

생활비와 목표 자금이 한 계좌에 섞이는 문제를 풀기 위해, 도담 전용 계좌 하나에 돈을 모으고 목표별 세이프박스에 금액을 배정하게 했다. 목표에 담기·꺼내기는 이체 없이 내부 배정 원장에만 기록한다. 최종 피드백에서 세이프박스 개념을 먼저 설명해야 한다는 의견을 받아 이 구분을 요구사항으로 명확히 했다.

  • 배정은 “얼마를 더”가 아니라 변경 후 배정 총액을 지정한다. 같은 요청이 반복돼도 중복 배정되지 않는다.
  • 현재 목표에 담을 수 있는 최대 금액은 전용 계좌 잔액 − 다른 목표 배정 합계다.

예를 들어 도담 계좌에 50만 원이 있고 여행에 20만 원, 비상금에 10만 원을 담았다면 미배정액은 20만 원이다. 여행 배정액을 30만 원으로 바꾸면 10만 원을 추가 배정한 것이며, 금융망 이체가 새로 생기지 않는다.

2. 계산은 서버가, 설명은 AI가 맡는다

AI 코치 토리는 서버의 계산 결과를 설명하고, 자연어 질문을 서버의 계산 도구 8종에 연결한다. 금액·심각도·추천 순위는 서버가 정한다.

  • 필수 금액이 없거나 대상 대출·목표를 특정할 수 없으면 임의로 고르지 않고 되묻는다.
  • AI 답변의 숫자를 서버 계산값·사용자 입력과 대조하고, 맞지 않으면 템플릿 답변으로 바꾼다.
  • AI 호출이 실패해도 이미 계산한 결과는 유지한다.

3. 계산할 수 없는 값을 0이나 임의 날짜로 채우지 않는다

금융 수치에서 “0원”과 “계산 불가”는 다른 의미다. 자료 부족·저축 속도 부족·예측 범위 초과는 사유와 함께 계산 불가로 제공하고, 실제 0원·거래 없음·조회 실패와 구분한다. 소비 예측은 관측 월이 3개 미만이면 예측하지 않고, 개선 효과는 비교할 완료 월이 생기기 전까지 측정 대기로 둔다.

4. 목표 조회와 시뮬레이션이 같은 계산식을 쓴다

“월 10만 원을 더 저축하면?”의 답이 목표 화면의 예상 달성일과 어긋나면 비교 자체를 믿을 수 없다. 같은 기준일·금융상태에서 행동 전후를 비교하고, 목표 조회와 시뮬레이션의 날짜 계산식을 하나로 맞췄다. 여러 행동을 함께 비교할 때는 각각의 단축일을 단순 합산하지 않는다.

대표 인수 시나리오

조건·행동 기대 결과
잔액 50만 원, 다른 목표 30만 원 상태에서 현재 목표에 30만 원 배정 최대 20만 원이므로 거부한다.
배정 20만 원을 반복 지정 40만 원이 되지 않고 이동 이력도 늘지 않는다.
“카페를 줄이면?”처럼 금액 없이 질문 금액을 되묻고 임의 금액을 적용하지 않는다.
관측 월이 2개뿐인 사용자의 소비 예측 사유와 함께 빈 예측을 제공하고 리포트의 나머지 정보는 유지한다.
