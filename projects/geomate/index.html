프로젝트 개요

**GEOMATE(지오메이트)**는 학생이 자기 문제의 도형을 돌리고, 펼치고, 잘라 보고, 보조선을 그으면서 관계를 이해하도록 돕는 2D·3D 기하 학습 앱입니다. 혼자서 학습을 시작하고, 막혔을 때 다음 시도를 찾아가는 경험을 목표로 합니다.

수학학원 지도 경험에서 출발해 현재 6인 팀으로 개발하고 있습니다. 저는 PM·프론트엔드·AI를 맡아 문제 정의와 학습 흐름, 기능 우선순위와 검수 기준을 정리하고, 태블릿 화면과 사진 해석을 개발·검증하고 있습니다.

주 대상은 중학교 1학년 도형과 초등 도형 학습 학생입니다. 중2·3의 닮음·피타고라스·원의 성질 등은 후속 확장으로 두고 있으며, 초등 활동과 추가 기능의 첫 배포 범위는 아직 확정하지 않았습니다.

진행 상태는 2026년 10월 22일 기록 기준입니다. 팀 제품 개발과 별도의 PoC 검증을 병행하고 있으며, 아래 영상은 기획 단계의 모션 시안입니다. 기술 스택은 현재 PoC 기준입니다.

문제 정의와 설문 근거

학원에서 학생을 지도하며, 공식을 알고 있어도 도형 속 관계를 찾지 못해 풀이를 시작하지 못하는 모습을 봤습니다. 입체 문제에서는 고정된 평면 그림만으로 가려진 면이나 단면, 전개도를 떠올려야 하는 부담도 있었습니다.

문제를 **‘정답을 모른다’에서 ‘무엇을 관찰하고 어떤 조작을 시도해야 할지 모른다’**로 구체화했습니다. 주 사용자는 스스로 문제를 탐색하는 학생이고, 강사는 학생이 어떤 관찰·조작·도움에서 막혔는지 확인하는 보조 사용자로 정했습니다.

자체 설문의 2026년 10월 15일 중간 집계는 응답 92명이며, 학생 70%·성인 30%로 구성됐습니다.

확인한 내용 설문에서 확인한 응답 기획에 연결한 점
막히는 지점 도형에서 막히는 이유 질문에서 ‘어떤 성질·공식을 쓸지 모름’ 43.9% 관계를 관찰할 방향과 다음 시도를 안내
기능 선호 ‘그린 선·식의 잘못된 부분 확인’과 ‘막힌 단계에서 다음 힌트’ 각각 32명 학생의 작업을 유지하며 진단·재시도하도록 설계
사용 기대 사용 의향 74명, 학습에 도움이 될 것이라는 응답 77명 실제로 혼자 사용할 수 있는지 후속 검증

질문별 응답 기준을 구분해 해석하고, 이 결과는 어려움과 사용 기대의 근거로 활용했습니다. 학습 효과는 실제 학생의 조작과 설명을 관찰해 별도로 확인할 계획입니다.

핵심 기획 결정

1. 관찰과 조작을 학습의 시작점으로 배치

정답 제출 이후에만 도구를 열면, 막힌 학생은 탐색을 시작하기도 어렵습니다. 그래서 회전·확대·기본 관찰과 도움 요청은 제출 전에도 사용할 수 있도록 설계했습니다.

반면 문제의 목표 정답을 직접 드러내는 단면이나 접기 결과는 먼저 예상한 뒤 비교하도록 하고, 공개 조건은 활동별로 정하기로 했습니다. 학생이 멈추고 되돌리고 시점을 바꿔 자신의 예상을 시험할 수 있는지가 중요한 기준입니다.

2. 힌트를 받은 뒤 학생의 시도로 돌아오도록 설계

힌트는 관찰 질문 → 시도할 조작·보조도구 → 새 관계와 이유 → 학생의 재시도로 이어지게 했습니다. ‘어느 두 면이 평행할까요?’, ‘옆면을 펼쳐 보면 경로가 어떻게 바뀔까요?’처럼 다음 행동을 선택하도록 돕는 방식입니다.

잘못 그린 선을 진단하더라도 맞은 선과 기존 작업을 유지하고 일부를 고쳐 다시 시도할 수 있어야 합니다. 곧바로 답에 닿지 않는 보조선도 어떤 관계를 만들었고 어디에 한계가 있는지 비교하도록 계획했습니다.

PoC에는 규칙 추론·각 근거·보조선과 입체 단계형 힌트가 있습니다. 현재 상태에 맞춘 AI 방향 안내와 학생의 독립적인 재시도까지 이어지는지는 다음 검증 과제입니다.

3. 계산의 정답과 학습 가능한 모델을 따로 평가

원기둥 안에 공 네 개가 들어가는 문제를 사진으로 해석했을 때, 계산값은 맞았지만 원기둥과 공 하나가 별도 탭에 표시된 사례가 있었습니다. 학생이 살펴봐야 하는 배치와 접촉 관계가 화면에 드러나지 않았습니다.

이 사례를 계기로 평가 기준을 정답 일치에서 도형의 배치·관계 보존, 관찰할 보조도구와 다음 행동의 적절성까지 넓혔습니다. 여러 입체를 한 장면에 배치하고, 반투명·단면·분해 보기로 관계를 보여주는 기능을 보완하고 있습니다.

사진 해석도 같은 기준으로 다룹니다. AI는 조건과 엔진 입력의 초안을 만들고, 엔진 검증과 학생 확인을 거쳐 모델에 연결합니다. 입력 형식이 맞아도 원본 조건을 잘못 옮겼을 수 있으므로 원문·생성 그림의 대조를 별도 검증 항목으로 뒀습니다.

사용자 흐름과 제공 범위

자체 예제 또는 개인 사진 → 조건 확인 → 관찰·예상·자유 조작 → 방향 도움 → 재시도 → 관계와 이유 비교 → 다른 배치에 적용

단계 학생이 하려는 일 설계 기준
시작 내 문제를 조작 가능한 도형으로 보고 싶다 자체 예제로 시작하거나 사진 해석 초안의 조건을 확인
탐색 다른 방향에서 보거나 변화를 시험하고 싶다 회전·확대와 지원되는 접기·펼치기·절단·분해 사용
도움 막힌 지점에서 다음 시도를 찾고 싶다 관찰 질문과 보조도구, 단계형 힌트 연결
수정 기존 작업을 살리면서 다시 시도하고 싶다 맞은 선·필기·조건 보존과 수정·되돌리기
비교 내 예상과 실제 관계가 어떻게 다른지 알고 싶다 예상과 결과를 비교하고 관계·이유 확인
적용 다른 시점이나 배치에서도 이해했는지 확인하고 싶다 가려진 요소·단면·대응 관계를 새 조건에서 예상

이 표는 제품의 설계 기준입니다. PoC의 현재 구현 범위와 구분해 관리합니다. 특히 자유 그리기, 도형 수치 편집, 저장·복원·내보내기 등 독립 작업 공간의 추가 요구사항은 배포 시점이 미정입니다.

학생의 회전·확대·조작은 엔진과 렌더러에서 처리하고, AI 호출은 사진 해석과 필요한 방향 안내로 제한하도록 설계했습니다. 조작 반응과 사진 해석의 대기·비용을 함께 고려하기 위한 결정입니다.

담당 역할과 현재 검증

  • PM: 현장 경험과 설문을 문제 정의에 연결하고, 독립 학습·자유 조작·공간감각의 우선순위를 기능과 검수 기준으로 구체화
  • 프론트엔드: 도형 표시·조작·펜 입력과 보조도구를 태블릿의 탐색 흐름으로 연결
  • AI: 사진의 조건·관계를 엔진 입력 초안으로 옮기고, 해석 오류·그림 품질·응답 시간·비용을 구분해 평가

현재 PoC에는 평면·입체 표시, 규칙 추론과 단계형 힌트, 보조선 후보 검증, 접기·펼치기·회전·분해, 흔한 실수 진단과 완성 도형 검사가 있습니다. 팀 제품의 계정·저장·반 현황 등과의 연결은 별도 상태로 관리합니다.

자동 테스트·TypeScript와 Python 교차 검사·브라우저 검사·사진 해석 평가를 진행했습니다. 각 결과는 해당 실행 범위의 기록으로 관리하며, 학생의 독립 학습이나 공간감각 향상과는 별도로 검증합니다. 세부 구현과 실행 수치는 아래 상세 영역에 정리했습니다.

다음 검증과 완료 기준

확인할 것 완료를 판단할 기준
혼자 시작하기 교사 설명 없이 예제를 시작하고 필요한 도구를 찾는가
예상과 조작 스스로 시점·중간 상태·보조도구를 골라 예상을 시험하는가
도움과 재시도 막혔을 때 힌트를 이해하고 자기 시도로 돌아오는가
다른 배치에 적용 다른 방향에서도 가려진 요소·단면·대응 관계를 예상하고 이유를 설명하는가
사진·모델 일치 원본 조건과 생성된 모델의 배치·관계를 대조할 수 있는가
태블릿 사용 실제 기기에서 펜·손바닥·손 조작과 화면 방향·접근성을 확인했는가

원본 문항의 사람 검수와 목표 태블릿 검증도 남아 있습니다. 자체 문항으로 튜토리얼·시연을 구성하고, 개인 사진은 본인 학습에만 사용하며 타인 공유나 모델 학습에는 사용하지 않는 방향으로 이용 범위를 정했습니다.

GEOMATE에서 기획의 기준은 학생이 도형을 보고, 직접 시도하고, 도움을 받아 다시 탐색할 수 있는가입니다. 다음 개발과 검증에서도 이 흐름이 실제로 이어지는지를 확인하려고 합니다.

설계·구현 상세

학습 인터랙션, PoC 구현·검수 기록, 시스템 구성과 모델·비용 검토 펼치기

학습 인터랙션과 추가 요구사항

혼자 시작하고 탐색을 이어가는 흐름

자체 예제 또는 개인 사진 → 조건 확인 → 관찰·예상·자유 조작 → 방향 도움 → 재시도 → 관계와 이유 비교 → 다른 배치에 적용

관찰·예상·도움·재시도는 반복할 수 있습니다. 기본 회전·확대·관찰과 도움 요청을 정답 제출 뒤로 일괄 잠그지 않습니다. 문제의 목표 정답을 직접 드러내는 단면·접기 결과는 먼저 예상한 뒤 비교하도록 설계하며, 활동별 공개 조건은 별도로 정합니다.

자유로운 모델 조작과 공간 관계 비교

학생이 시점을 바꾸고, 지원되는 접기·펼치기·절단·분해의 중간 상태를 오가며 같은 점·선·면을 추적하도록 합니다. 완성된 애니메이션을 보는 데서 그치지 않고 멈추고 되돌리고 다른 방향에서 자신의 예상을 시험하는 경험이 핵심입니다.

문제의 조건을 유지하는 조작과 조건을 바꾸는 탐구를 구분하고, 원래 시점·상태로 돌아갈 수 있어야 합니다. 가려진 면 예상, 전개도와 입체 대응, 절단 전 단면 예상, 부분과 전체의 관계를 공간감각 검수 대상으로 삼습니다. 모든 도형·임의 절단·범용 3D 편집을 지원한다는 의미는 아닙니다.

단면·전개도·보조선

단면에서는 학생이 그린 선의 평면성·닫힌 경계·평행 관계 등 지원 규칙을 확인하고, 관련 부분과 다시 시도할 방향을 제시합니다. 맞은 선은 유지하고 일부만 고칠 수 있어야 합니다.

전개도에서는 접기 전후의 면·모서리·꼭짓점 대응을 비교합니다. 입체를 펼치면 어떤 관계가 보이는지 학생이 직접 확인하게 합니다.

평면에서는 학생이 보조선을 고르고 그어 새 관계를 만들거나 다른 선과 비교합니다. 바로 답에 닿지 않는 시도도 생긴 관계와 한계를 설명하고, 유효한 다른 탐색을 허용합니다.

관찰과 다음 행동을 돕는 힌트

힌트는 관찰 질문 → 시도할 조작·보조도구 → 새 관계와 이유 → 학생의 재시도로 이어지도록 합니다. 예를 들어 "어느 두 면이 평행할까요?", "옆면을 펼쳐 보면 경로가 어떻게 바뀔까요?"처럼 학생이 다음 행동을 선택하도록 돕습니다.

PoC에는 평면 규칙 추론·각 근거·보조선과 입체 단계형 힌트가 있습니다. 현재 상태에 맞춘 AI 방향 안내는 다음 검증 과제입니다. 계산 과정의 나열이나 완성된 풀이를 보여 주는 것만으로 학습 기능을 완료했다고 보지 않습니다.

직접 그리기와 독립 작업 공간

현재 PoC의 문제 연결 그림판은 학생이 완성한 도형의 길이·각·관계를 검사합니다. 내부 작도 단계가 나타내는 관계를 검사하는 것이며, 학생의 자·컴퍼스 사용 순서를 채점하지 않습니다.

추가 요구사항에는 문제 없이 시작하는 자유 그리기, 손으로 그린 사각형의 편집 도형 변환, 정육면체·직육면체·직사각형 프리셋, 변·각 수치 수정, 작업 저장·복원·실행 취소·PNG 내보내기가 있습니다. 풀이 영역 배치·크기 조정과 방향별 저장도 포함합니다. 기존 그림판이 이 전체 요구를 충족한 것은 아니며 배포 시점은 미정입니다.

PoC 구현과 검수 기록

1~5단계에 걸쳐 구현한 PoC를 같은 학습 기준으로 다시 검토하고 있습니다. 아래 구현 상태와 학생이 혼자 쓸 수 있는가·공간감각 향상에 도움이 되는가의 검증은 구분합니다.

단계 PoC에서 구현한 것 학습 관점의 보완·검수
1 · 도형·그림 평면 좌표 엔진·2D SVG, 입체 표시·치수·시점 개선 학생이 모델을 읽고 다른 방향에서도 같은 관계를 찾는가
2 · 규칙·근거·힌트 규칙 추론·각 근거·단계형 힌트 도움을 찾아 다음 관찰·조작을 스스로 선택하는가
3 · 보조선 보조선 후보 검증과 학생 선의 관계·도달 가능성 피드백 다른 시도를 비교·되돌리며 새 관계를 이해하는가
4 · 입체 학습 접기·펼치기·회전·분해와 입체 힌트 중간 상태·새 시점에서도 대응·단면·부분/전체를 예상하는가

TS·Python 교차 검사와 교재 유형 대조, 브라우저 검사를 진행했습니다. 예를 들어 0~5단계 마무리 당시 교차 검사 318/318, 브라우저 40/40 통과 기록이 있습니다. 이후 변경은 별도 실행 범위로 검증했으며, 이 수치를 최신 제품 전체의 통과율이나 학습 효과로 해석하지 않습니다. 원본 문항의 사람 검수와 목표 태블릿의 펜·손바닥·접근성 검증도 남아 있습니다.

시스템 구성

현재 PoC는 React·TypeScript·Three.js 화면, 브라우저 Worker의 기하 엔진, FastAPI·SymPy 기반 Python 서비스로 구성합니다. 사진은 VLM이 조건·관계와 엔진 요청 초안으로 해석하고, 엔진 검증과 학생 확인을 거쳐 모델에 연결합니다.

회전·확대·접기·단면 표시 등 지원되는 조작은 엔진·렌더러에서 처리합니다. 자유 조작마다 AI를 호출하지 않고, 사진 해석과 필요한 방향 안내에 AI를 사용하도록 설계합니다. PoC 구현과 계정·저장·반 현황 등의 팀 제품 연동은 별도 상태로 관리합니다.

기술적 검토와 실행 당시 기록

아래 모델 비교와 비용은 원문에 기록된 실행·단가 기준의 자료입니다. 이번 문서 수정에서 모델 평가나 API 비용 측정을 다시 실행한 것은 아닙니다.

위 이미지는 초기 기술 검토 시안입니다. 표시된 후보 라이브러리·모델을 모두 도입한 것은 아니며, 현재 PoC 구성과 후속 계획은 아래 내용을 기준으로 구분합니다.

값이 맞아도 학습할 그림이 없으면 실패

원기둥 안에 공 네 개가 꼭 맞게 들어가는 문제를 사진으로 해석했을 때 계산값은 맞았지만, 원기둥과 공 하나가 별도 탭에 표시됐습니다. 학생이 발견해야 하는 공의 배치·접촉·바깥 입체와의 관계가 보이지 않았습니다.

이 사례를 계기로 평가 기준을 정답 일치에서 학습 가능한 모델과 도구 생성까지 넓혔습니다. 여러 입체를 한 장면에 배치하고, 반투명·세로 단면·분해 보기로 관계를 드러내는 기능을 보완하고 있습니다. 맞는 계산이 그림·학습 경험의 성공을 보장하지 않는다는 사례입니다.

사진 해석은 초안, 바른 관계는 엔진으로 확인

사진에서 지름을 반지름으로 읽거나, 점 이름·작도 순서·색칠 영역을 계약과 다르게 생성하는 실패가 발생했습니다. VLM 출력은 초안으로 두고 조건과 불확실한 부분을 확인하게 하며, 기하 관계·측정값·판정은 엔진으로 검증합니다.

현재는 엔진 오류가 발생하면 같은 사진·이전 초안·오류 정보를 보내 한 번 수정 요청하고, 실패 요청 수가 더 많아지면 첫 초안을 유지하는 경로가 있습니다. 형식 검사를 통과해도 사진을 바르게 읽었다는 보장은 없으므로 그림·원문 조건의 대조가 필요합니다. 렌더링한 그림을 원본과 비교해 되묻는 경로는 후속 검증 과제입니다.

펜 입력과 학생 작업 보존

PoC에서는 2D 획의 끝점을 화면상의 꼭짓점·모서리 후보에 스냅하고 기하 참조에 연결합니다. 후보가 모호하면 학생이 확인하게 하며, 화면상 가까움만으로 기하 동치를 확정하지 않습니다. 임의의 면 위 획 전체를 인식하는 범용 기능과는 구분합니다.

자체 예제와 개인 업로드의 이용 범위

교재 문항·정답·해설·이미지를 서비스 문항 은행에 탑재하지 않습니다. 튜토리얼·시연은 팀이 새로 만든 자체 문항으로 구성하고, 교재 분석은 내부 지원 유형·검증 자료로만 사용합니다.

학생이 올린 사진은 본인 학습에만 사용하며 다른 학생에게 공유하거나 모델 학습에 사용하지 않습니다. 기존의 타인 간 공유 모델 캐시 계획은 제외했습니다. 검증된 입력의 완전 일치 재사용은 본인 문제·자체 예제 범위의 제안이며, 라벨·치수·조건·목표 일치와 오류·수정 시 무효화 정책을 확정해야 합니다.
