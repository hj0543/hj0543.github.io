2f:T63c4,<h2 id="project-geomate-section-0">프로젝트 개요</h2>
<p>**GEOMATE(지오메이트)**는 학생이 자기 문제의 도형을 돌리고, 펼치고, 잘라 보고, 보조선을 그으면서 관계를 이해하도록 돕는 2D·3D 기하 학습 앱입니다. <strong>혼자서 학습을 시작하고, 막혔을 때 다음 시도를 찾아가는 경험</strong>을 목표로 합니다.</p>
<p>수학학원 지도 경험에서 출발해 현재 6인 팀으로 개발하고 있습니다. 저는 <strong>PM·프론트엔드·AI</strong>를 맡아 문제 정의와 학습 흐름, 기능 우선순위와 검수 기준을 정리하고, 태블릿 화면과 사진 해석을 개발·검증하고 있습니다.</p>
<p>주 대상은 중학교 1학년 도형과 초등 도형 학습 학생입니다. 중2·3의 닮음·피타고라스·원의 성질 등은 후속 확장으로 두고 있으며, 초등 활동과 추가 기능의 첫 배포 범위는 아직 확정하지 않았습니다.</p>
<p><strong>진행 상태는 2026년 10월 22일 기록 기준</strong>입니다. 팀 제품 개발과 별도의 PoC 검증을 병행하고 있으며, 아래 영상은 기획 단계의 모션 시안입니다. 기술 스택은 PoC와 팀 앱 개발 기준입니다.</p>
<p>상단 화면은 2026년 10월 27~28일 개발 중인 태블릿 앱에서 서로 다른 예제를 개발자가 조작한 캡처입니다. 사진 해석의 연속 과정이나 학생 사용 기록은 아닙니다.</p>

<h2 id="project-geomate-section-2">핵심 기획 결정</h2>
<h3>1. 관찰과 조작을 학습의 시작점으로 배치</h3>
<p>정답 제출 이후에만 도구를 열면, 막힌 학생은 탐색을 시작하기도 어렵습니다. 그래서 <strong>회전·확대·기본 관찰과 도움 요청은 제출 전에도 사용할 수 있도록</strong> 설계했습니다.</p>
<p>반면 문제의 목표 정답을 직접 드러내는 단면이나 접기 결과는 먼저 예상한 뒤 비교하도록 하고, 공개 조건은 활동별로 정하기로 했습니다. 학생이 멈추고 되돌리고 시점을 바꿔 자신의 예상을 시험할 수 있는지가 중요한 기준입니다.</p>
<h3>2. 힌트를 받은 뒤 학생의 시도로 돌아오도록 설계</h3>
<p>힌트는 <strong>관찰 질문 → 시도할 조작·보조도구 → 새 관계와 이유 → 학생의 재시도</strong>로 이어지게 했습니다. ‘어느 두 면이 평행할까요?’, ‘옆면을 펼쳐 보면 경로가 어떻게 바뀔까요?’처럼 다음 행동을 선택하도록 돕는 방식입니다.</p>
<p>잘못 그린 선을 진단하더라도 맞은 선과 기존 작업을 유지하고 일부를 고쳐 다시 시도할 수 있어야 합니다. 곧바로 답에 닿지 않는 보조선도 어떤 관계를 만들었고 어디에 한계가 있는지 비교하도록 계획했습니다.</p>
<p>PoC에는 규칙 추론·각 근거·보조선과 입체 단계형 힌트가 있습니다. 현재 상태에 맞춘 AI 방향 안내와 학생의 독립적인 재시도까지 이어지는지는 다음 검증 과제입니다.</p>
<h3>3. 계산의 정답과 학습 가능한 모델을 따로 평가</h3>
<p>원기둥 안에 공 네 개가 들어가는 문제를 사진으로 해석했을 때, 계산값은 맞았지만 원기둥과 공 하나가 별도 탭에 표시된 사례가 있었습니다. 학생이 살펴봐야 하는 배치와 접촉 관계가 화면에 드러나지 않았습니다.</p>
<p>이 사례를 계기로 평가 기준을 <strong>정답 일치에서 도형의 배치·관계 보존, 관찰할 보조도구와 다음 행동의 적절성까지</strong> 넓혔습니다. 여러 입체를 한 장면에 배치하고, 반투명·단면·분해 보기로 관계를 보여주는 기능을 보완하고 있습니다.</p>
<p>사진 해석도 같은 기준으로 다룹니다. AI는 조건과 엔진 입력의 초안을 만들고, 엔진 검증과 학생 확인을 거쳐 모델에 연결합니다. 입력 형식이 맞아도 원본 조건을 잘못 옮겼을 수 있으므로 원문·생성 그림의 대조를 별도 검증 항목으로 뒀습니다.</p>

<h4>혼자 시작하고 탐색을 이어가는 흐름</h4>
<p><strong>자체 예제 또는 개인 사진 → 조건 확인 → 관찰·예상·자유 조작 → 방향 도움 → 재시도 → 관계와 이유 비교 → 다른 배치에 적용</strong></p>
<p>관찰·예상·도움·재시도는 반복할 수 있습니다. 기본 회전·확대·관찰과 도움 요청을 정답 제출 뒤로 일괄 잠그지 않습니다. 문제의 목표 정답을 직접 드러내는 단면·접기 결과는 먼저 예상한 뒤 비교하도록 설계하며, 활동별 공개 조건은 별도로 정합니다.</p>

<h4>자유로운 모델 조작과 공간 관계 비교</h4>
<p>학생이 시점을 바꾸고, 지원되는 접기·펼치기·절단·분해의 중간 상태를 오가며 같은 점·선·면을 추적하도록 합니다. 완성된 애니메이션을 보는 데서 그치지 않고 멈추고 되돌리고 다른 방향에서 자신의 예상을 시험하는 경험이 핵심입니다.</p>
<p>문제의 조건을 유지하는 조작과 조건을 바꾸는 탐구를 구분하고, 원래 시점·상태로 돌아갈 수 있어야 합니다. 가려진 면 예상, 전개도와 입체 대응, 절단 전 단면 예상, 부분과 전체의 관계를 공간감각 검수 대상으로 삼습니다. 모든 도형·임의 절단·범용 3D 편집을 지원한다는 의미는 아닙니다.</p>
<h4>단면·전개도·보조선</h4>
<p>단면에서는 학생이 그린 선의 평면성·닫힌 경계·평행 관계 등 지원 규칙을 확인하고, 관련 부분과 다시 시도할 방향을 제시합니다. 맞은 선은 유지하고 일부만 고칠 수 있어야 합니다.</p>
<p><img src="/projects/geomate/section-diagnosis.png" alt="단면 진단 예시"></p>
<p>전개도에서는 접기 전후의 면·모서리·꼭짓점 대응을 비교합니다. 입체를 펼치면 어떤 관계가 보이는지 학생이 직접 확인하게 합니다.</p>

<p>평면에서는 학생이 보조선을 고르고 그어 새 관계를 만들거나 다른 선과 비교합니다. 바로 답에 닿지 않는 시도도 생긴 관계와 한계를 설명하고, 유효한 다른 탐색을 허용합니다.</p>
<h4>관찰과 다음 행동을 돕는 힌트</h4>
<p>힌트는 <strong>관찰 질문 → 시도할 조작·보조도구 → 새 관계와 이유 → 학생의 재시도</strong>로 이어지도록 합니다. 예를 들어 &quot;어느 두 면이 평행할까요?&quot;, &quot;옆면을 펼쳐 보면 경로가 어떻게 바뀔까요?&quot;처럼 학생이 다음 행동을 선택하도록 돕습니다.</p>
<p>PoC에는 평면 규칙 추론·각 근거·보조선과 입체 단계형 힌트가 있습니다. 현재 상태에 맞춘 AI 방향 안내는 다음 검증 과제입니다. 계산 과정의 나열이나 완성된 풀이를 보여 주는 것만으로 학습 기능을 완료했다고 보지 않습니다.</p>
<h4>직접 그리기와 독립 작업 공간</h4>
<p>현재 PoC의 문제 연결 그림판은 학생이 완성한 도형의 길이·각·관계를 검사합니다. 내부 작도 단계가 나타내는 관계를 검사하는 것이며, 학생의 자·컴퍼스 사용 순서를 채점하지 않습니다.</p>
<p>추가 요구사항에는 문제 없이 시작하는 자유 그리기, 손으로 그린 사각형의 편집 도형 변환, 정육면체·직육면체·직사각형 프리셋, 변·각 수치 수정, 작업 저장·복원·실행 취소·PNG 내보내기가 있습니다. 풀이 영역 배치·크기 조정과 방향별 저장도 포함합니다. 기존 그림판이 이 전체 요구를 충족한 것은 아니며 배포 시점은 미정입니다.</p>

<h3>시스템 구성</h3>
<p>현재 PoC는 React·TypeScript·Three.js 화면, 브라우저 Worker의 기하 엔진, FastAPI·SymPy 기반 Python 서비스로 구성합니다. 사진은 VLM이 조건·관계와 엔진 요청 초안으로 해석하고, 엔진 검증과 학생 확인을 거쳐 모델에 연결합니다.</p>
<p>회전·확대·접기·단면 표시 등 지원되는 조작은 엔진·렌더러에서 처리합니다. 자유 조작마다 AI를 호출하지 않고, 사진 해석과 필요한 방향 안내에 AI를 사용하도록 설계합니다. PoC 구현과 계정·저장·반 현황 등의 팀 제품 연동은 별도 상태로 관리합니다.</p>

<h4>값이 맞아도 학습할 그림이 없으면 실패</h4>
<p>원기둥 안에 공 네 개가 꼭 맞게 들어가는 문제를 사진으로 해석했을 때 계산값은 맞았지만, 원기둥과 공 하나가 별도 탭에 표시됐습니다. 학생이 발견해야 하는 공의 배치·접촉·바깥 입체와의 관계가 보이지 않았습니다.</p>
<p>이 사례를 계기로 평가 기준을 <strong>정답 일치에서 학습 가능한 모델과 도구 생성</strong>까지 넓혔습니다. 여러 입체를 한 장면에 배치하고, 반투명·세로 단면·분해 보기로 관계를 드러내는 기능을 보완하고 있습니다. 맞는 계산이 그림·학습 경험의 성공을 보장하지 않는다는 사례입니다.</p>
<h4>사진 해석은 초안, 바른 관계는 엔진으로 확인</h4>
<p>사진에서 지름을 반지름으로 읽거나, 점 이름·작도 순서·색칠 영역을 계약과 다르게 생성하는 실패가 발생했습니다. VLM 출력은 초안으로 두고 조건과 불확실한 부분을 확인하게 하며, 기하 관계·측정값·판정은 엔진으로 검증합니다.</p>
<p>현재는 엔진 오류가 발생하면 같은 사진·이전 초안·오류 정보를 보내 한 번 수정 요청하고, 실패 요청 수가 더 많아지면 첫 초안을 유지하는 경로가 있습니다. 형식 검사를 통과해도 사진을 바르게 읽었다는 보장은 없으므로 그림·원문 조건의 대조가 필요합니다. 렌더링한 그림을 원본과 비교해 되묻는 경로는 후속 검증 과제입니다.</p>

<h4>자체 예제와 개인 업로드의 이용 범위</h4>
<p>교재 문항·정답·해설·이미지를 서비스 문항 은행에 탑재하지 않습니다. 튜토리얼·시연은 팀이 새로 만든 자체 문항으로 구성하고, 교재 분석은 내부 지원 유형·검증 자료로만 사용합니다.</p>
<p>학생이 올린 사진은 본인 학습에만 사용하며 다른 학생에게 공유하거나 모델 학습에 사용하지 않습니다. 기존의 타인 간 공유 모델 캐시 계획은 제외했습니다. 검증된 입력의 완전 일치 재사용은 본인 문제·자체 예제 범위의 제안이며, 라벨·치수·조건·목표 일치와 오류·수정 시 무효화 정책을 확정해야 합니다.</p>
